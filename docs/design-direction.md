# HETRICH 디자인 방향과 레퍼런스 비교

HETRICH는 이건하의 개인 제품 스튜디오이며, 방문자가 세 제품의 역할과 현재 제공 범위를 이해하고 제품으로 이동하는 것이 첫 번째 목적이다. 2026년 10월 7일 확인한 레퍼런스 중 Estudio의 여백과 Adam dev의 담백한 소개 구성을 조합해 적용한다. 테두리 대신 간격, 배경의 명도 차이, 글자의 크기로 위계를 만든다.

## 레퍼런스 비교

5sdesign 라이브러리에서 다섯 사례의 공개 프리뷰를 브라우저로 확인했다. Inspo도 보조 탐색했으나 사용자 선호에 따라 최종 후보는 모두 5sdesign에서 선정했다. 유료 에셋이나 프롬프트를 복제하지 않고 시각적 원칙만 참고했다.

평가 항목은 제품 스튜디오 적합성 35%, 절제감 30%, 정보 전달력 20%, 다중 페이지 확장성 15%다. 각 항목을 10점 만점으로 평가하고 가중 합계에 10을 곱했다. 점수는 디자인 판단이며 전환율이나 사용자 테스트 결과가 아니다. 공개 프리뷰 중심의 평가이므로 원본 사이트 전체의 사용성 평가는 아니다.

1. [Estudio](https://www.5sdesign.art/library/estudio) — **90점**. 항목별 9/9/9/9. 밝은 바탕, 넉넉한 빈 공간, 중앙 타이포그래피와 명확한 행동 유도가 특징이다. 메시지가 먼저 읽히고 작은 스튜디오의 개성이 살아 가장 적합하다. 네온 버튼과 영문 이탤릭은 가져오지 않고, 한글 산세리프와 차분한 블루로 번역한다.
2. [Adam dev](https://www.5sdesign.art/library/adamdev) — **86점**. 항목별 9/9/8/8. 인물과 짧은 소개를 나란히 둔 개인 개발자 포트폴리오 분위기다. 신뢰와 운영 주체 전달에 적합하다. HETRICH에서는 사진 대신 제품과 운영 사실을 먼저 보여주고, 제작자 소개는 하단과 About에 둔다.
3. [Ous](https://www.5sdesign.art/library/ous) — **67점**. 항목별 7/6/7/7. 따뜻한 풍경과 대형 로고로 자유로운 제작자 커뮤니티 분위기를 만든다. 여유 있는 구성과 간결한 CTA는 유용하지만 풍경이 제품보다 먼저 기억될 가능성이 있다. 몰입형 배경은 채택하지 않는다.
4. [1Brain](https://www.5sdesign.art/library/1brain) — **57점**. 항목별 6/5/6/6. 차가운 블루, 금속성 인물 렌더, 대형 산세리프가 기술 스튜디오 인상을 만든다. 기술적 정체성은 가깝지만 작은 생활 제품에는 규모감과 장식이 강하다. 낮은 채도의 블루만 참고한다.
5. [MOSS](https://www.5sdesign.art/library/moss) — **46점**. 항목별 4/4/6/5, 가중 합계 45.5를 반올림. 분홍색 하늘과 떠 있는 오브젝트가 몽환적인 소비재 브랜드 분위기를 만든다. 중심 메시지는 선명하지만 장면이 제품의 실용성과 경쟁한다. HETRICH 전체 방향으로는 부적합하다.

보조 탐색: [Inspo](https://inspomcp.dev/). 서로 다른 제품의 사례를 모아 볼 수 있으나 이번 결정에는 5sdesign의 실제 공개 프리뷰를 우선했다.

## 구현 규칙

- **폰트**: 한글 Noto Sans KR, 영문 Manrope의 고정 굵기 400·500·600·700, 작은 영문 분류 DM Mono. 패키지에 포함된 폰트를 자체 제공해 Google Fonts 다운로드에 의존하지 않는다. 본문 16px, 행간 1.72~1.9, 주요 제목 500, 제품명 600. 한글 제목에는 이탤릭을 쓰지 않는다.
- **색상**: 바탕 `#f8f7f3`, 텍스트 `#242923`, 보조 텍스트 `#646861`, 강조 `#3e55a5`. HIS는 세이지 `#e9eee5`, 칼로리 제품은 샌드 `#f0e7dd`. 강한 블루·형광 연두·오렌지가 동시에 경쟁하던 구성을 줄인다.
- **간격**: 최대 폭 1280px, 좌우 여백 20px~72px, 데스크톱 섹션 간격 64~112px, 모바일 56px. 본문과 CTA 사이에는 24~32px를 둔다. 제품 간격은 세로 48px, 가로 40px를 기본으로 한다.
- **첫 화면**: 가운데 정렬한 브랜드 메시지와 한 개의 주요 CTA, 보조 About 링크. 별도 제품 인덱스를 반복하지 않고 바로 아래의 제품 섹션으로 연결한다.
- **제품**: 세 제품을 동일한 구조로 비교한다. 작은 식별 아이콘, 제품명, 한국어 상태, 역할 한 문장, 행동 버튼 한 개만 둔다. 반복 설명·특징·GitHub·개발 메모·상태 범례는 메인에서 제외하고 상세 제공 범위와 GitHub는 Products 페이지로 연결한다.
- **테두리**: 카드, 상태 배지, 특징 목록, 텍스트 링크, 일반 버튼에는 장식 border를 쓰지 않는다. 입력 필드와 키보드 포커스는 조작 가능성을 분명히 하기 위해 경계를 유지한다.
- **모양과 움직임**: 주요 버튼은 둥근 단색 면, 제품 식별 아이콘 배경만 12~15px 곡률. 자동 재생이나 패럴랙스 없이 hover의 미세한 변화만 사용하며 reduced motion 설정을 존중한다.
- **연속성**: Products, Insights, About, Contact에도 같은 팔레트, 버튼, 폰트, 낮은 테두리 밀도를 적용한다. 실제 제품 상태와 링크, 문의 검증, 발행물 데이터 경계는 유지한다.

## 검증 범위

홈과 기존 네 개 라우트의 반응형 배치, 320~1440px 화면에서의 넘침, CTA 터치 크기, 키보드 메뉴, 포커스, WCAG A/AA 자동 검사, reduced motion, 이미지와 한글 타이포그래피를 확인했다.

## 반응형과 정보 밀도 개선

제품 섹션의 밀도는 반복되는 정보에서 비롯됐다. 영문 분류, 영문 상태, 한국어 개발 단계, 제목, 리드, 상세 설명, 특징, 별도 메모와 버튼 두 개가 한 제품 안에서 경쟁했다. 첫 화면의 인덱스도 제품 목록을 반복했다. 여백을 늘리기보다 메인의 역할을 제품 선택으로 좁혔다.

- 1001px 이상에서는 세 제품을 동일한 3열로 배치하고 subgrid로 제목·상태·설명·버튼의 기준선을 맞춘다. 긴 제품명 때문에 짧은 제품의 제목 아래에 고정 여백을 만들지 않는다.
- 701~1000px에서는 제품 식별 정보, 역할, 행동을 가로형 목록으로 배치한다. 700px 이하에서는 제품별 세로 목록으로 바뀐다. 슬라이더나 숨겨진 제품 없이 세 제품을 모두 보여준다.
- 같은 375px 브라우저 뷰포트에서 섹션 텍스트는 공백 제외 670자에서 182자로, 링크는 7개에서 4개로, 높이는 약 2356px에서 871px로 줄었다. 측정은 DOM의 innerText와 bounding rectangle 기준이며 글꼴·브라우저에 따라 높이는 조금 달라진다.
- 메인에서 제거한 상세 설명과 GitHub는 Products 페이지에 남아 있고 하단의 ‘제품별 기능과 제공 범위’ 링크로 연결된다. 제품별 실제 사용 링크와 개발 상태는 유지한다.
- 기종별 캡처를 비교해 Windows WebKit의 가변 글꼴 렌더링이 지나치게 가늘어지는 차이를 발견했다. 같은 글꼴의 고정 굵기를 자체 제공하도록 바꾼 뒤 WebKit·Chrome 캡처에서 제목, 본문, 버튼의 굵기를 다시 확인했다. 실제 iOS의 동일한 결함으로 단정하지 않는다.

## 모바일 기종별 확인

실기기가 아닌 Playwright 기기 에뮬레이션이다. 설치된 Playwright의 기기 정의를 사용해 viewport, 사용자 에이전트, 터치, 픽셀 배율을 함께 적용한다. iPhone은 Windows WebKit, Pixel은 Chrome에서 실행한다.

- iPhone SE 1세대: viewport 320×568, DPR 2, WebKit.
- iPhone 13: viewport 390×664, screen 390×844, DPR 3, WebKit. 도구의 기본 프로필이 브라우저 UI 영역을 제외한 viewport를 사용한다.
- Pixel 7: viewport 412×839, screen 412×915, DPR 2.625, Chrome.

각 프로필에서 홈의 제품 이동, 고정 헤더에 가려지지 않는 제목, 44px 이상 터치 영역, 제품 상태, 텍스트 넘침, WCAG A/AA 자동 검사를 수행한다. 제품 상세 링크와 터치 메뉴를 실제로 사용하고 홈·Products·About·Contact·Insights의 세로 및 가로 배치도 확인한다. 기존 Chrome·WebKit 320~1440px 검사도 유지한다.

스크린샷은 `outputs/iphone-se-products.png`, `outputs/iphone-13-products.png`, `outputs/pixel-7-products.png`와 각 `*-home.png`에 저장된다. 실기기 Safari나 보조기술 사용자 테스트는 별도이며, 외부 서비스에서의 제출이나 프로덕션 배포는 이번 검증에 포함하지 않는다.

최종 프로덕션 빌드에서 전체 Playwright 검사 25개가 통과했다. `npm run build`, `npm run lint`, `git diff --check`도 통과했으며, 세 기종의 최종 캡처에서 글꼴 굵기·긴 제품명 줄바꿈·버튼 배치를 육안으로 재확인했다.

## 2026-10-07 실제 자료 반영
앞선 아이콘 중심 카탈로그 규칙을 업데이트한다. 제품별 한 문장·버튼 하나는 유지하고, L-Proof 아티클 목록과 HIS 개발 화면 일부를 같은 높이의 미리보기로 보여준다. 칼로리 제품도 후속으로 제공된 실제 화면을 반영했다. 목록에서는 기록 일부를 보여주고, 크게 보기 링크로 수정 응답을 포함한 원본 전체를 확인한다.
일반적인 제작 원칙 세 개는 익명으로 묶은 사용자 피드백과 확인된 구현(분수 해석, 음식별 계산 내역, 대화 기록)으로 교체했다. 근거 커밋과 파일은 product-sources.md에 기록했다. 발행물은 최신 한 편의 요약과 두 편의 제목으로 압축했다. Contact는 수신 설정이 없으면 이메일을 제시하고 입력 폼을 숨긴다.
남은 자료: HIS의 개인정보 없는 기억 입력/결과 화면, 최신 코드의 공개 배포 범위. 이를 확인하기 전에는 영상 데모, 제품 사용 성과, 추가 기능의 배포 완료를 주장하지 않는다.

### 발행물 목록 정리
메인의 비대칭 발행물 배치를 날짜·제목·화살표의 단일 목록으로 교체했다. 첫 글만 요약을 제공하고 각 행의 고정 구분선 하나로 읽는 흐름을 만든다. 링크의 브라우저 기본 밑줄과 제목 hover 밑줄을 모두 제거했으며 hover는 색상과 2px 화살표 이동만 사용한다. 키보드 포커스 외곽선은 유지한다. 모바일에서는 날짜가 제목 위로 이동하고, 모션 감소 설정에서는 이동·전환을 생략한다.
